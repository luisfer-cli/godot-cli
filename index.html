Terminal-first Godot documentation

Build Godot projects from the shell.

godot-cli is a small CLI for creating, inspecting, editing, checking, running, and exporting Godot 4 projects without opening the Godot editor for routine work.

What this tool is for

Godot is excellent, but many everyday tasks are just structured text edits: creating scenes, adding nodes, wiring scripts, setting the main scene, adding input actions, creating simple maps, and running checks. godot-cli makes those tasks scriptable.

Use godot-cli for

  • Project bootstrap and settings.
  • Simple scene and node changes.
  • Script creation/attachment.
  • Input actions and autoloads.
  • ASCII level maps and tiny terminal UIs.
  • Godot headless checks, runs, tests, and exports.

Use Godot/Neovim for

  • Complex inspector edits.
  • Native TileSet/TileMap authoring.
  • Visual layout and animation tuning.
  • Deep .tscn/.tres resource editing with LSP support.

Godot mental model

If you are new to Godot, learn these four ideas first. godot-cli is built around them.

Scenes

A scene is a saved tree of nodes, usually a .tscn file. A player, enemy, level, UI panel, or entire game screen can be a scene.

Nodes

Nodes are the building blocks. Node2D, CharacterBody2D, Sprite2D, and Camera2D are common 2D nodes.

Resources

Resources are data assets: scripts, textures, scenes, audio, materials, shapes, and custom data. Godot paths usually look like res://player.gd.

Scripts

GDScript files attach behavior to nodes. A script typically starts with extends CharacterBody2D or another Godot class.

In the editor, you manipulate these visually. In godot-cli, you manipulate the same files with commands.

Install

git clone https://github.com/luisfer-cli/godot-cli.git
cd godot-cli
make install

The installer creates ~/.local/bin/gd and installs the Python package files under ~/.local/lib/godot-cli.

Add this to your shell config if needed:

export PATH="$HOME/.local/bin:$PATH"

Check the install

gd self-test

First game workflow

This creates a tiny Godot project with a main scene, player node, player script, jump input, and a compiled level scene.

mkdir MyGame && cd MyGame

gd project init MyGame

gd scene create Main --root Node2D
gd scene main Main

gd node add Main Player --type CharacterBody2D
gd script create player.gd --extends CharacterBody2D
gd script attach Main Player player.gd

gd input add jump Space

gd map new Level1 24 14
gd map edit Level1
gd map compile Level1 LevelScene

gd check --godot
gd run

After this, open player.gd in your editor and write movement code. Use the Godot Scene LSP for completions and project-aware paths.

Project settings

project.godot is an INI-like file. godot-cli can initialize it and edit simple settings.

gd project init MyGame
gd project info
gd scene main Main
gd project setting set display/window/size/viewport_width 1280
gd project setting set display/window/size/viewport_height 720
gd project setting get display/window/size/viewport_width

scene main writes application/run/main_scene, which tells Godot what to run by default.

Scenes and nodes

Scenes are stored as .tscn files. godot-cli edits them conservatively: it changes the lines it understands and preserves unknown blocks.

gd scene create Main --root Node2D
gd node add Main Player --type CharacterBody2D
gd node add Main Sprite --type Sprite2D --parent Player
gd node set Main Player position "Vector2(100, 200)"
gd node get Main Player position
gd node duplicate Main Player Enemy
gd node rename Main Enemy Slime
gd node remove Main Slime
gd tree Main

Tip: node paths

Most node commands accept a node name or path, like Player or Player/Sprite.

Scripts and signals

gd script create player.gd --extends CharacterBody2D
gd script attach Main Player player.gd
gd signal connect Main ready Player Player _on_ready
gd script list

Script attachment adds an external script resource to the scene and writes script = ExtResource(...) on the selected node.

Signals are appended as Godot connection entries. For complex signal workflows, use Godot or edit with LSP support.

Input actions and autoloads

Input actions live in project.godot and let scripts ask for semantic actions instead of raw keys.

gd input add move_left A
gd input add move_right D
gd input add jump Space
gd input list
gd input remove jump

Autoloads are globally available singleton scripts.

gd script create game_state.gd --extends Node
gd autoload add GameState game_state.gd
gd autoload list
gd autoload remove GameState

ASCII maps

ASCII maps are the fastest terminal-first way to block out 2D levels. A dot (.) is empty; every other character becomes a node when compiled.

P#.
..#
gd map new Level1 16 9
gd map check Level1
gd map edit Level1
gd map compile Level1 LevelScene --tile-size 16

Legend

Create levels/map.legend to map characters to Godot node types:

[legend]
#=StaticBody2D
P=CharacterBody2D
C=Camera2D

Why not native TileMap yet?

Native TileMap editing needs real TileSet/atlas metadata. godot-cli intentionally avoids inventing a partial TileMap editor. Use ASCII maps for layout, then move to Godot/Neovim when you need full tileset details.

Godot binary integration

godot-cli does not replace the engine. It calls the real Godot binary for running, checking, and exporting.

gd check --godot
gd run
gd run --godot /opt/Godot_v4/godot

If godot is not installed in PATH, pass --godot with the binary path.

Exports and tests

Export presets are read from export_presets.cfg.

gd export list
gd export run Linux build/game.x86_64

For project tests, configure a command in project.godot:

[gd]
test_command=godot --headless --path . --script res://test_runner.gd
gd test

Neovim + Godot Scene LSP

For serious text editing, pair this CLI with godot-scene-lsp, the companion LSP server.

The LSP focuses on working with scenes, nodes, and resources without opening Godot. It provides:

  • Scene .tscn completions.
  • Node path completions like Player/Sprite.
  • res://... resource completions for scripts, scenes, textures, audio, and project files.
  • Godot class, keyword, callback, and project symbol completions.
  • Document symbols, definitions, references, hover, and simple diagnostics.

Neovim example

vim.lsp.start({
  name = 'godot-scene-lsp',
  cmd = { 'godot-scene-lsp', '--stdio' },
  root_dir = vim.fs.root(0, { 'project.godot', '.git' }),
})

Recommended workflow: use godot-cli for repeatable operations, use Neovim + LSP for rich text editing, and use Godot only for visual/engine-specific work.

Recipes

Create a player scene

gd scene create Player --root CharacterBody2D
gd node add Player Sprite --type Sprite2D
gd node add Player Collision --type CollisionShape2D
gd script create player.gd --extends CharacterBody2D
gd script attach Player Player player.gd

Create UI root

gd scene create UI --root Control
gd node add UI Menu --type VBoxContainer
gd node add UI StartButton --type Button --parent Menu
gd node set UI Menu anchors_preset 8

Prepare export

gd check --godot
gd export list
gd export run Linux dist/my-game.x86_64

Known limits

  • .tscn support is conservative and line-preserving, not a full Godot resource parser.
  • Native TileMap/TileSet editing is not implemented; use ASCII maps or Neovim/Godot for full tileset metadata.
  • The curses TUIs are intentionally small helpers, not full editor replacements.
  • Input mapping supports basic keys first.
  • On Windows, curses may require a compatible terminal environment.
